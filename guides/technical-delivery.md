# 技术交付：从 URL 到真实可读页面

阅读条件：不收录、技术审计、框架改动、上线、迁移、爬虫异常。按问题选择检查，别把所有建议转为强制配置。

平台规则核验日期为 2026-09-17。实施时重新查询受影响平台的官方技术要求、功能支持状态与指标定义；本指南提供实施和验证方法，不替代平台规范。

## URL 和索引约定

先建立 URL 类别清单：主内容、分类、筛选、搜索、分页、语言、历史版本、账户、暂存、已下线。每类明确保留索引、合并、不可索引、权限保护或删除的业务原因。索引数量最大化不是目标。

| 观察 | 决策与验证 |
|---|---|
| 多主机、协议、斜杠或路径大小写 | 从部署和产品约定确定唯一目标；核对重定向、canonical、内部链接、sitemap 一致。不要默认所有站采用同一尾斜杠规则 |
| canonical 到不同 URL | 判断内容和意图是否真正等价，检查目标可用与索引意图。分页、语言翻译、不同产品不因模板相似就合并 |
| URL 参数 | 区分跟踪参数、排序/筛选、真实内容参数。不要删除有语义的参数；避免无限组合进入抓取队列 |
| 内部搜索/空分类 | 判断是否是独立有价值落地页；无价值组合控制发现和索引。对已收录 URL 不能仅靠 robots 删除 |
| 删除/停产/迁移 | 真正等价替代才永久重定向；否则依据产品选择保留有用历史页或返回 404/410。不要全部跳首页 |
| noindex 与 robots 禁止并存 | 引擎需能读取 noindex 才能处理；先明确移除目标和当前索引状态，再调整。敏感内容用认证保护 |
| canonical/noindex 互相矛盾 | 还原各自目的和生成来源，不能凭标签优先级猜引擎最终处理 |

canonical 一般是信号而非保证。只有可获取时才使用 URL Inspection 或引擎报告确认实际选中的 canonical；`site:` 搜索只能作线索，不能精确统计收录率。

## HTTP、CDN 与 WAF

- 诊断线上问题或验收已发布改动时，对准确生产 URL 发 GET，记录时间、请求 UA、状态、重定向每跳、最终 URL、关键响应头和正文指纹。HEAD 可辅助但不能替代 GET 内容检查；尚未发布的代码或预览改动在相应环境验证。
- 检查软 404、200 挑战页、登录页、同一个 SPA 壳响应不存在路径、循环和多跳。测试一个明确不存在的路径以了解路由兜底，不扫描无限路径。
- 对缓存问题核对 Cache-Control、Age、Vary、ETag、Last-Modified 及平台缓存标记；分别记录源站和边缘。查询参数绕过缓存只能诊断，不能当生产规范 URL 已修复的证明。
- 个性化、登录和受地区限制页面不能套用统一公共缓存。缓存寿命与价格、库存、法规等新鲜度要求一致；不要为 GEO 盲目延长 TTL。
- 自定义 UA 模拟与真实机器人访问分开。200/403 差异是调查线索；核对官方 IP 或反向/正向 DNS 方法及 WAF 日志后再判断真实爬虫。
- WAF 放行尽量针对官方验证机器人和需要公开的路径，不能把优化爬虫变成全站关闭防护。
- 检查重定向和错误页中的 X-Robots-Tag / Link 响应头，并保留 agent-specific 指令。重复头可能有意义，不应被普通字典覆盖。

## robots、sitemap 和发现

- 分别处理各协议/主机/端口的 robots.txt。记录实际匹配的 UA 组、URL 路径和规则；注释出现机器人名字不代表配置。
- 遵守平台的匹配和错误处理规则。robots 的 404、5xx、重定向、HTML 伪装内容不能全部转为“允许”或“禁止”。不自己用 substring 实现规则优先级。
- 检查 meta robots 与 X-Robots-Tag 的 noindex、nosnippet、max-snippet 等，以及正文元素上的局部 `data-nosnippet` 属性；后者不是 meta/header 指令，也不自动限制整页。按产品定义其用途，不把每个限制都一键删除。
- sitemap 只列拟索引的规范 URL；检查索引文件、分片、压缩文件、格式与平台限制。处理相对 URL、重复、重定向、错误状态、noindex 和错误主机。
- `lastmod` 表示内容的实质更新时间；构建、抓取、版权年份或样式修改不能自动刷新所有页面日期。
- XML 合法、提交已接收、已抓取、已收录是不同结果。IndexNow 是变化通知，不是收录保证；Google Indexing API 只按官方支持的内容类型使用。
- HTML 链接应有真实可解析的 href，入口不能只靠点击事件或站内搜索。分页可发现的 URL 与无限滚动可以共存。不要给所有分页 canonical 到第一页。
- 内链围绕用户下一步和主题关系；分析孤立页、断链、过深路径和不合理 hub。导航链接数量、固定点击深度不是通用排名门槛。

## 原始响应与渲染

Google 有渲染能力；其他检索/抓取产品的行为各异。不要笼统说“AI 都不执行 JS”。对于公开关键内容，可靠的服务端 HTML/预渲染通常减少依赖，但需要按现有框架选择 SSR、SSG 或其他合适方案。

涉及渲染、抓取内容缺失、跨输出事实或交互问题时，对模板代表页比较相关层；不因普通静态修改默认检查全部层：

1. 原始 HTTP HTML 中的标题、正文、链接、关键事实、索引与 canonical。
2. 浏览器渲染后的对应内容和 DOM。
3. 关键交互之后的真实用户状态。
4. 若有权限，平台自己的抓取/渲染观测。

查找 hydration 覆盖、流式 metadata、client-only 数据、占位价格、空 skeleton、JS 错误、资源被屏蔽、懒加载正文、无限滚动及 locale 重定向。框架会按 UA 改变 metadata 流式行为时，核对当前版本和文档，不能泛化旧漏洞。

从同一数据源生成页面元信息和正文，避免 route-level 与全局默认标签叠加。一个清楚的主标题通常最易理解；多个 H1 本身不是可证明的排名惩罚。标题和描述应准确、独特、符合页面意图；字符长度只是展示诊断，不设全球统一硬阈值。

对于 CDN Markdown 协商、`.md` 镜像或文档导出，核对内容等价、链接、更新时间、Vary 与缓存隔离。机器摘要不能比正文价格更新得慢，也不能拥有正文没有的优惠或资历。

## 结构化数据

- 先确定实体和页面类型，再选当前有效的 Schema.org 类型和搜索平台支持的功能。合法 schema 不等于 rich result 合格，更不等于更易被 AI 引用。
- 与用户可见内容及真实业务相符；稳定 `@id` 连接 Organization、真实作者、产品、页面、面包屑等，避免同一实体多个互相矛盾 ID。
- 区分 JSON 可解析、语义/类型正确、必需字段/URL/日期有效、可见事实一致、平台功能资格和线上实测六层。
- 不伪造评分、评论、价格、供货、薪资、地点和资质。收集目录条目并不使本站成为这些产品的卖家或创建者。
- FAQ 内容可对用户有用，但 Google FAQ 富结果已自 2026-05-07 停止展示，相关文档于 2026-06-15 移除；旧的“仅限权威政府/医疗站”规则已过时。不要为了恢复该展示批量加 FAQ schema。HowTo、课程、图书等具体搜索功能也可能变化，实施当天查询官方更新日志并检查支持状态。
- 不把 schema 数量作为 KPI。多个插件/模板输出同一实体时先解决冲突。

## 性能、可访问性和用户任务

有 CrUX/RUM 时用相关设备/地区和实际 URL/源站范围的第 75 百分位数据。当前常用 CWV 良好阈值是 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1；使用时复核官方定义。没有现场数据明确标注，不用一次 Lighthouse 分数替代。

定位 LCP 资源/服务端延迟、交互长任务、第三方脚本、字体与图片导致的布局偏移。优先修实际瓶颈；首屏关键图不盲目 lazy-load，给图像尺寸和响应式资源，避免无条件 preload 全站资源。

检查移动布局、键盘操作、语义控件、可读对比、目录锚点、表格横向滚动和 CTA。可见答案不应被广告、弹窗或首屏大块空白遮挡。性能修复后再次完成核心用户任务，而不只跑基准测试。

## 按交付范围选择验收证据

按改动风险选择对应 URL 类别的正常页与关键边界、受影响规则的行为检查，以及必要的原始/渲染对照。代码或预览任务在约定层验收；已发布改动验证规范 URL 的生产结果，不能用本地结果代替。未覆盖的真实机器人、索引和现场性能状态如与结论有关，应标为未知。不要用相同生成器产出的字面值当作独立验收标准。

必要检查通过后，仅因新增改动、失败或未解决的具体疑点扩大或重复测试；不为满足固定检查数量增加无关回归。
