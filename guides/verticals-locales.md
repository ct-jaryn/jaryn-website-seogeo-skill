# 业务类型、国际化和页面生命周期

阅读条件：识别到相应站型/页面类型时使用，避免把电商、SaaS 或文档规则套到所有站。

实施时查询目标平台当前的本地化、结构化数据与垃圾内容政策；平台支持范围和业务适用性必须分别核验。

| 站型 | 高价值页面与证据 | 特别容易出错 |
|---|---|---|
| SaaS / 产品 | 定位、用例、价格、比较、集成、文档、变更说明；真实功能和试用路径 | 年付价冒充月付；“替代品”页只换品牌词；功能下线仍留 SEO 承诺 |
| AI 工具/资源目录 | 可信产品事实、可用地区、任务分类、编辑标准、实测与研究状态、停运/合并状态 | 虚构评分和评论；摘抄 vendor 文案；空分类；跨域复制同一目录 |
| 电商 | 商品/变体、库存、价格/币种、运送与退货、对比、merchant feed | feed/schema/正文不一致；筛选无限 URL；所有变体硬 canonical 同一页；虚构评价；AI 商品图或商品文案未按 Merchant Center 规则标明 |
| 本地服务 | 实际地址/服务范围、营业时间、预约、价格规则、资质和真实案例 | 虚构办公室/服务城市；批量城市名替换；名称地址电话矛盾 |
| 出版/知识 | 原创信息、作者/编辑、方法、来源、主题索引、更正与版本 | 自动刷日期；无依据“实测”；为了覆盖关键词批量重写同一故事 |
| 文档/API | 任务入口、概念、how-to、reference、示例、版本、错误处理、弃用迁移 | 旧 API 示例；深链/锚点失效；canonical 全部到最新版导致历史任务无答案 |
| 平台/UGC | 有用内容、真实贡献者、审核/反滥用、内容状态与发现 | 空用户页与垃圾帖子被索引；登录墙和付费内容配置不正确 |

结合当前 Google 支持的搜索功能选择 Product、Article、JobPosting、Event、SoftwareApplication、Organization、BreadcrumbList 等；类型存在不代表符合该平台富结果条件。不要自动加全部类型。对于资质/专业建议要求按业务风险提供真实审阅；不可编造专家背书。

电商若用生成式 AI 制作商品图或商品数据，遵守当前 Merchant Center 规则：AI 生成图片需带 IPTC 元数据，`DigitalSourceType` 为 `TrainedAlgorithmicMedia`；AI 生成的商品名、说明等要单独标明为 AI 生成。这不是 Google 搜索富结果的额外 schema 要求。页面、feed 和 schema 仍须与可见事实一致。

在适用时，Merchant Center 与商家资料中的现行信息有助于商品和本地详情出现在生成式 AI 回答及其他搜索结果中。商家智能体是可选的对话体验，不是收录或 GEO 资格。

有真实门店或上门服务时，才对照 Google 商家资料的现行展示准则。核对名称、地址或服务区域、电话、网站、营业时间和类别是否与网站及门头、印刷品牌一致；类别只描述核心业务，不堆砌。每个商家一份资料。没有门店却批量建城市资料，按虚构地点处理。资料完整、评价数量或帖子频率都不是地图排名证明。其他平台的商家资料单独核对该平台现行规则。

## 程序化目录和 marketplace

对象与集合页分开维护。产品/商家/工具同名时使用稳定 ID，别用可变化标题做唯一标识。入口可按用户任务组织，排序和赞助透明。新、已验证、待核验、过期、下线、被合并的实体有明确生命周期。

集合有足够有用条目和解释才值得单独发布。筛选/排序改变内容和用户意图时逐类决定 URL 与索引策略；不是所有参数都该删除，也不是所有组合都该可索引。零结果页的状态与交互由产品决定，不一律返回200或404。

撤下商品仍可能服务维修、历史版本、迁移或替代任务。保留有用信息、明确状态及真实替代，比无差别重定向更合理。决定删除后使用合适状态并更新链接、sitemap、feed 和通知。

## 国际化

先确定真正服务的语言/地区、需求、编辑能力、可售/可用范围、货币和法律/支持信息，再扩展 URL。语言数不是质量指标。只翻译菜单、主体仍是英语的页面不能写成完整本地化。

- 页面有稳定可链接的语言 URL，用户能切换并保持相同任务。
- 避免强制 IP/语言跳转让用户和爬虫无法选择；自动推荐语言时仍有明确入口。
- 翻译页通常使用其适当语言 canonical；不要一概 canonical 到原文。hreflang 只连真正对应、有效、可索引的版本。
- 检查 hreflang 自指与互返、语言/地区代码、主机/路径、对应 URL、最终状态和实际语言。截至 2026-10-10，Google 文档要求每个语言版本列出自身及其他版本；备用 URL 必须带协议且为绝对地址；两边不互指的标记会被忽略。Google 不用 hreflang 或 HTML `lang` 判断语言。语言码用 ISO 639-1，区域码用 ISO 3166-1 Alpha 2；示例用 `en-GB` 表示英国。`UK` 不是该标准的区域码，不能写成 `en-UK`，也不能只写国家码。`es-419` 这类不在这两套标准中的代码不受支持。中文可用 `zh-Hans` / `zh-Hant`，区域可选。
- HTML、HTTP header、XML sitemap 三种标法对 Google 等效，择一维护。混用必须一致；三套同时上没有搜索好处，也更容易互相冲突。生成后核对实际标签是否包含当前 URL 的自指，不要假设框架 metadata API 会自动补上。
- `x-default` 用于不匹配语言的后备，尤其是语言选择器或自动跳转首页。没有这些场景时，不因缺少它判不合格。
- 不要把上述 Google 处理直接套到 Bing 或其他引擎。那些产品的帮助页以当时打开的原文为准。
- 本地化包括主要内容、图片文本、例子、单位、货币、价格、产品可用性和支持渠道；内容更新需传播到相关版本。
- 不为没有真实服务能力的地域生成门页。不把机器翻译量作为需求证明。

国际化验收至少覆盖一个完整语言组和一个缺失翻译/下线版本边界，检查真实页面语言与 URL/metadata 一致。locale 参数和默认地区交付差异需要保留请求条件。

## 图片、视频、交互工具

按内容需求选择原创图、解释图、屏幕演示、真实视频或工具。需要被发现的图片用 HTML `img` 的 `src` 嵌入；CSS 背景图不能代替它。`srcset` 或 `picture` 仍要有 `src` 后备。文件应可读取，扩展名与类型相符。截至 2026-10-10，Google 文档列出的常见格式包括 BMP、GIF、JPEG、PNG、WebP、SVG 和 AVIF。

文件名只是很弱的主题线索：短而可描述即可，本地化图片连文件名一起翻译。不要为了关键词批量改名。替代文本描述图片并服务无障碍，不要用关键词堆满 `alt`。图片靠近相关正文。首选预览可用 `primaryImageOfPage`、主体的 `image` 或 `og:image` 提示；选与内容相关的高分辨率图，避免用站标、大段文字图或极端宽高比充当代表图。这是提示，不是合格门槛，也不保证被选为预览。

图片站点地图只在普通抓取发现不了图片时考虑，CDN 图可以写进 `image:loc`。不要因为没有图片站点地图判不合格。体积和清晰度按实际体验取舍；数据 URI 内嵌会增大 HTML。Merchant Center 对 AI 商品图的标明要求见上文，不要套成普通网页 schema 要求。视频页、字幕、缩略图和适用 schema 仍按平台当前指导与内容量决定。

有用的计算器、生成器和模板要能完成真实任务，输入输出和计算假设可解释，同时有可读说明。纯截图文字或嵌入第三方 widget 不应是唯一关键答案。不要为了被 AI 调用自动开放写接口或部署新协议。
