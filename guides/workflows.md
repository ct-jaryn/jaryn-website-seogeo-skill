# 工作流与完成证明

阅读条件：完整迭代、上线、迁移、紧急异常、持续优化。流程可裁剪，验收证据不能用意图替代。

## 完整网站迭代

1. **目标与归属**：确认业务任务、市场、站点和仓库/部署关系；读取项目规则，保护已有工作。明确本轮是否含生产发布及持续监测，沿用已有授权。
2. **可复用基线**：页面类别/索引意图、真实事实源、路由与内容清单、代表页、业务指标、关键 HTTP/DOM 证据。已有可用数据优先复用但标日期。
3. **需求和对照研究**：查看目标查询和真实竞品页面，找原创信息或任务服务的缺口；不把热门网站全部配置照搬。
4. **找主要瓶颈**：技术阻塞、内容准确性、页面价值、发现/内链、体验、外部依赖分别定位。排序解释依据，不只给数值。
5. **实现与扩展**：优先修改数据源、共享模板和高业务价值页面；按风险批量推广到约定范围。
6. **验收与再评估**：对改动和边界验证，发布在授权范围内完成；仍有高价值可控事项则继续下一轮。
7. **结果与测量**：交付已实施、已验证、待观察、受阻四类事实。需要等待索引/引擎传播时建立可执行的复测计划或已授权调度。

大任务可将只读需求研究、技术检查、内容评估和数据分析并行。写代码时划分文件所有权，主执行者汇总冲突、验证生产状态。不要为小任务机械创建多个代理。

## 上线与迁移

上线前建立 URL/索引清单和主机约定，检查生产环境是否残留 noindex、认证、测试数据、错误 canonical 或不完整 hreflang。验收搜索关键页面与核心转化，不只首页。

迁移前保存重要 URL 的流量/链接/内容基线及旧→新映射；只有语义等价映射才重定向。试运行高价值路径和异常路径，核对内链、sitemap、schema、语言、feed、缓存与日志。适用时按官方流程处理站点迁移工具和更新通知。

发布后直接验证旧 URL、精确新 canonical、状态链和实际内容，观察错误、抓取、索引和业务变化。保留回滚方案及触发条件。不可把“站点迁移工具已接受”当作搜索损失不会发生的证明。

## 不收录或流量下降

先核实数据异常：日期范围、时区、过滤、追踪代码、权限、数据延迟、品牌/非品牌与设备/地区分层。确定开始时间、受影响页面模板和未受影响对照组。

随后按证据排查变更、URL/索引指令、状态/渲染、WAF/缓存、站点安全问题、内容需求、季节性和搜索平台更新。检查是否有人先前宣称修复，找到其证明停在哪一层。

诊断请求输出原因、证据和最小修复方案；已经要求修复则实施并验证。不要在没有原因的情况下批量删页、换域名、重写全部内容或请求全部重新索引。

## 每条发现的输出契约

```
id / 严重度 / URL类别与样本量
观察：可复现的现象
证据：时间、URL、请求/数据条件、原始产物路径
影响：哪个业务任务受影响，已知范围与未知范围
归因：已证实根因或尚待验证假设；拥有该行为的层
修改：具体数据源/文件/配置，以及依赖
验收：什么当前证据足以证明修复
结果：未改 / 已改待验证 / 验证通过 / 外部待观察 / 受阻
```

严重度按实际后果定：关键页面大面积不可达或错误事实优先；中低风险体验建议不能靠“GEO 分差”升级为阻断。

## 完成审计

从原请求重新推导要求，逐项确认当前事实。不要从已做的工作倒推一个较小的完成定义。

| 项目 | 完成所需证据 |
|---|---|
| 网站/范围正确 | 配置/部署或官方属性对应目标；覆盖和未覆盖有清单 |
| 事实正确 | 重要内容与来源一致，过期信息和跨输出冲突处理 |
| 改动有效 | 对应模板和边界的实际行为验证；相关回归通过 |
| 已发布（如果在范围内） | 正式 URL 内容和响应正确，能关联本次改动 |
| 页面有价值 | 用户任务可完成、内容增量和维护来源可说明 |
| 效果（如果承诺测量） | 实际引擎/分析证据，样本、条件和局限明确 |
| 后续工作 | 高价值可执行项已处理，剩余依赖/等待有具体动作 |

“做到当前能做到的极限”是以下三件事一起成立：网站可控的高影响问题得到解决；内容与用户任务达到证据支持的高标准；持续改进的测量和复测方法已建立。没有私有数据时不能保证全局最优，但不能因此停止公开检查与已授权实施。

停止本轮的合理原因：约定范围全部实现并验证、必要外部结果尚待更新、下一步取决于缺失的重大决策/访问权限、或剩余建议无足够收益证据。不因清单很长、某个评分变绿、一次构建成功或第一批完成就提前结束。

输出应简洁：先说实际改变的用户/网站结果，再给关键验证和仍未知的效果。需要详细审计时把证据和逐项记录放可打开的产物，最终回复不要粘贴整份清单。
