# 测量与迭代实验

阅读条件：效果对比、GEO 监测、查询面板、转化、部署后传播。优先把业务问题转化为可观测假设，再选择指标。

平台报告和字段会变化。实施时按 [去哪里核对](lookup.md) 打开当前帮助，并以账号里实际可见字段为准；本指南不替代平台定义。

## 六层状态及证据

| 状态 | 合适证据 | 不能替代它的证据 |
|---|---|---|
| 实现正确 | 代码、数据、构建和针对性测试 | checklist 写了已完成 |
| 公开交付正确 | 规范生产 URL、响应、DOM、事实、版本 | 本地或带缓存绕过参数的预览 |
| 实际机器人到达 | 可信机器人身份的日志/官方工具观测 | 普通电脑换 UA 得到200 |
| 引擎实际索引 | 对应引擎 URL 检查/索引报告 | sitemap 或通知接收成功 |
| 指定体验引用 | 原始回答、来源 URL、条件和时间 | 技术准备度分数 |
| 有效业务结果 | 访问、关键事件、合格线索/收入的可解释数据 | 品牌提及数量或模型自评 |

不是每轮都有六层权限。明确已证实到哪一层、其余为何未知，照常推进网站可控工作。

## 官方数据优先，但尊重实际字段

Google Search Console 常规报告按查询、页面、国家、设备和搜索外观等实际可用维度分析，区分品牌/非品牌和模板类别；保留聚合方式、日期时区、过滤条件与数据延迟。均值排名不是固定排名；CTR 变化需要考虑展示位置与结果形态。自 2026-09-24 起，常规效果报告另有网页多模态搜索类型，覆盖智能镜头、Android 圈定即搜、上传到 Google 搜索的图片，以及 Chrome 的“搜索此图片”。文本查询与多模态查询分开看，不要合成一个 CTR。

截至 2026-10-10，Google 提供独立的生成式 AI 效果报告（搜索）；公开说明写明该分析于 2026-08-31 起全球推出。它统计 AI 概览和 AI 模式中、指向网站的链接向用户展示的次数，不含搜索实验室实验。Google 探索有另一份生成式 AI 效果报告，不要并进搜索报告。

维度是网页、国家/地区、设备和日期。网页按重定向后的最终到达 URL 分组，多数归到规范 URL 而非重复 URL。设备分桌面、平板和移动。日期为太平洋时间，可按天、周或月。搜索类型可过滤“网页：基于文本”和“网页：多模态”；后者与常规效果报告中的多模态过滤是同一类查询。不要凭空生成 AI queries、clicks 或 CTR。

计数口径：图表默认按资源汇总，同一条生成式 AI 结果里同一网站的两条链接计 1 次展示；加上 URL 过滤后按 URL 汇总。表格按国家、设备或日期分组时按资源汇总，按网页分组时按网页汇总。图表总数可以不同于表格总数。不要把这份报告与常规效果报告的展示相加；官方说明它包含常规效果报告网页搜索类型中的相应数据，多模态过滤也同时出现在两份报告中。低展示或已排除可能导致报告不可见。导出时界面上的 `~` 或 `-` 会变成 0。能否访问、字段和数据量以实际属性为准。图表虚线是仍在收集的初步数据。常规效果报告的行数与时间范围限制同样适用。

Bing Webmaster Tools 的 AI Performance 于 2026-02-10 以公开预览发布；其后站长博客未见替代定义。它覆盖 Microsoft Copilot、Bing 的 AI 摘要和部分合作方集成。Total Citations 是所选时间内作为来源展示的引用次数，不表示某条回答中的位置。Average Cited Pages 是所选时间范围内，每天作为来源展示的本站去重页面数的平均值，不是每日总和，也不是排名或权威。页面级数字是 URL 被引用的次数，不是重要性。Grounding queries 是样本，不是全部用户问题。账户字段以实际可见为准；预览公告不是帮助页的永久字段表。

分析工具中的 AI referrer 只覆盖可归因到站访问；无 referrer、移动端应用、复制链接和零点击引用会漏记。不能把 referrer 访问量当 AI 总影响，也不能将 direct 增长全部归因于 GEO。记录转化定义、去重方式、内部/机器人过滤和归因窗口。

## 固定问题面板

从业务需求建立版本化 panel：品牌事实、品类发现、比较、任务/用例、购买条件和地区问题。分别标注品牌提示与非品牌提示，避免通过在问题里写品牌名称人为抬高“发现率”。需要对比竞争者时记录品牌别名与域名匹配规则。

保持可比：prompt 原文、意图、语言、地域、引擎、产品界面/API、provider、模型（未知就写 unknown）、搜索开关、登录/会话条件、采集方式、日期窗口和重复轮次。UI 抓取与模型 API 必须分组。搜索结果摘录不能冒充独立调用所有 AI 产品。

保留原始回答/来源和错误，不仅留分数。分开记录：有效答案、拒答/无答案、错误、品牌是否出现、是否推荐、引用 URL、事实是否正确、是否有支持证据。品牌同名和链接短域/跳转需人工复核。

采样量按成本、波动和决策需要设定；早期可用一小组高价值问题做试点，不能称全市场份额。稳定面板与新增探索问题分开，问题增删要换 panel 版本。多次同日查询不保证统计独立。

## 指标定义与分母

- 运行成功率：有效回答数 / 发起次数，同时展示拒答和错误数。
- 品牌提及率：明确标注提及 true 的回答数 / 已完成提及判定的有效回答数。
- 推荐率：明确推荐数 / 已完成推荐判定的有效回答数，推荐与仅提及分开。
- 域名引用率：至少一个引用 URL 命中品牌域名的回答数 / 已知引用列表的有效回答数。
- 来源分布：按 URL/域名去重的引用计数；保留同一回答多次引用但说明去重口径。
- 面板内竞争占比：若需要，先定义使用品牌出现次数还是答案覆盖次数以及竞争者集合；标为“该面板的占比”，不叫市场占有率。
- 事实正确率/引用支持率：人工或经校准判定的正确/受支持样本数 / 已检查样本数；未知不能当正确。

空分母输出 `null / 无有效样本`。错误和验证码不是“没提到品牌”。`cited_urls: []` 表示已观察且无引用，`null` 表示不知道引用；两者不同。没有回复的 run 不参与可见性分母。

跨面板/日期/引擎汇总会受采样权重影响。先分层展示，聚合时保留固定权重及各层样本量；不要因昂贵引擎少跑就默默降低其影响。比前后变化同时报告样本量、成功率和条件变化。需要置信区间时按重复查询/日期聚类处理依赖，不假装所有响应独立。

本包 [summarize_observations.py](../scripts/summarize_observations.py) 仅本地汇总明确标注的数据，不自动评判答案、不查询模型、不推断因果。完整用法见 [工具与证据](tools-evidence.md)。

## 实验与资源分配

需要判断收益或决定推广的实验，记录现状/证据、假设、目标人群与页面、改动、主指标、保护指标、观察窗口、结果判定和回滚条件；[experiment-plan 模板](../assets/experiment-plan.example.json) 可裁剪。普通修错无需另建实验计划。有事实依据且成本可控的假设即可启动小规模验证，不要求预先证明收益。

优先把阻塞性错误和事实错误直接修复；不为了 SEO 实验保留已知错误。内容格式、摘要位置、内部链接和新页面策略可在匹配的页面组分批实施，以尚未改动的可比页面作对照。尽可能避免同时改 URL、标题、价格和内容后只归因于其中一项。

记录部署日期、实质更新、索引/抓取时间、算法更新、季节性和促销。迁移期、低样本或索引尚未刷新时，结论为不足以判断而非失败。置信度、观察窗口根据业务与波动选择，不统一宣称“两周见效”。

## 循环和停止条件

每轮：测量 → 找主要瓶颈 → 实施可控改动 → 验证 → 复测同样问题 → 判断继续、推广、回退或换假设。先完成仍可执行的高价值工作，再等待外部传播。

需要持续监测且用户已授权时，使用环境提供的调度机制，设置成本/频率、有效期和可行动变化通知；不在当前会话反复无意义刷新。未来复测任务应记录明确 URL/panel、条件和判定标准，不虚构已经监测。
